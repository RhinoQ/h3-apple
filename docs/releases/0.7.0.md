# 0.7.0 — VSA, SOL and optional X2

The local main branch retains **VSA as the default and SOL as an explicit alternative**.
Both use original LightX2V Ref2VA Turbo four-step v0.1. SOL now merges Turbo into the
BF16 base before W8G64 preparation, fixing the observed duplicate-person regression
in the qualified cases. Optional X2 supports landscape and portrait at 544p/576p.
Ordinary 768p remains available; **768p + X2 has been removed** from the public API.

This is the release documentation for the integrated **0.7.0 source checkout**.
The published release remains 0.6.0. The matching 0.7.0 native engine archive is
currently local: its manifest URL is deliberately unset. Installing a source wheel
on another computer requires the matching archive or the [documented native build](../development.md#build-the-engine-artifact).
No new release URL, remote benchmark or public binary is implied by this document.

Maintenance removes private experiment overrides and unused Wan/training code.
The public generation contract and retained numerical helpers are unchanged.
Frozen benchmark videos remain bound to their recorded build.
Cancellation no longer fails on macOS after the worker group has already exited;
permission errors against live processes are still reported.

## Choose a mode

| Mode | Useful observed behavior | Observed limitations |
| --- | --- | --- |
| VSA, default | Lower physical memory; better action-count or graphic-trajectory control in some comparisons | Reframing, partial face cropping and architectural geometry drift in other cases |
| SOL, optional | Faster complete calls in the frozen comparison; stronger composition in several portrait/architecture cases | More physical memory; repeated actions and overshoot/return in some tasks; not uniformly better quality |
| 544p + X2, either mode | Lower sampling cost and larger decoded frames; landscape and portrait supported | Reconstructs detail rather than recovering a high-resolution ground truth; cannot repair failed motion, identity or composition |

Use explicit `--mode VSA` / `--mode SOL`, and `--resolution 544p --x2` for the fast
profile. This profile name describes the benchmark request, not a new CLI flag.
Five-second tests are useful for iteration. Same seed across modes does not imply the
same random tensors, implementation or output. Neither mode silently falls back to the
other. See [X2 examples](../x2.md), [SOL migration](../install.md#upgrading-sol-models-in-the-source-checkout)
and [the public API](../api.md).

## Descriptive benchmark

The initial **0.1.0** portable benchmark edition contains 40 historical case families
and 152 recorded outputs, including successes, failures, pre-fix duplicates, graphics, small faces,
99/bobo stories and Tiangong architecture. It contains the original prompts, ordered
reference files, byte hashes, run metadata, source records, licenses, quality judgments,
a static comparison page and public-API replay scripts. It is prepared locally for
future independent publication; unresolved reference rights are marked local-review
only and excluded by its documented-input export option.
Later gallery editions can add historical tasks without changing this frozen comparison.

The main score uses **all five validation cases from one frozen product build**, each
at four routes. Calibration, old recipes and diagnostic controls are not pooled into
the score. The [machine-readable evidence](../evidence/v0.7.0-benchmark.json) contains
the exact requests, input hashes, original evaluations, source/model identities and
computed scores. Scores retain the recorded source identity; subsequent code cleanup
is not a new video-quality or performance evaluation.

| Route | Confirmed complete visual task success | Complete API median | Peak physical memory range |
| --- | ---: | ---: | ---: |
| VSA, ordinary 768p | 20% (1/5) | 492.5 s | 38.35–38.62 GiB |
| SOL, ordinary 768p | 60% (3/5) | 332.4 s | 58.56–58.70 GiB |
| VSA, 544p + X2 | 40% (2/5) | 233.8 s | 32.37–32.95 GiB |
| SOL, 544p + X2 | 60% (3/5; one further borderline result) | 174.7 s | 57.58–57.69 GiB |

Per-mode headline scores combine the two profiles: **VSA 30/100 (3/10), SOL 60/100
(6/10)**. These are five independent scenes repeated at two configurations, not ten
independent tasks. A borderline result is not a confirmed pass. The full visual task
must satisfy the frozen criteria; a pleasing frame alone is insufficient. Quality
severity distributions are separate from success, timing and memory; no weighted
composite conceals a failure.

These are known, method-disclosed Agent reviews on a 40-core M5 Max / 128 GiB, using
five-second, 120-frame outputs. Complete API timing includes checks and worker startup,
excludes initial model preparation, and has one measurement per slot. Review covered
all sequential thumbnails and selected full-resolution frames, not continuous playback
or subjective audio. The set is exposed and small; it cannot establish a universal
quality ranking, blind non-inferiority or multi-run performance confidence. In the
scored action case both modes fail the complete task, while later fresh diagnostic
examples show a VSA action advantage. The benchmark retains that distinction.

## Fixes and lessons that affected adoption

- **SOL duplicate-person regression:** applying Turbo at runtime to a quantized base
  and merging it into BF16 before quantization are different numerical recipes.
  FP32 merge → BF16 rounding → W8G64 preparation removed the observed duplication in
  the regression and two fresh portrait/landscape gates. It did not make every motion
  correct. The [controlled evidence](../evidence/sol-premerge-source.json) does not
  prove a universal vpipe bug, an incorrect SOL attention operator or bad adapter binding.
- **Prepared-model compatibility:** the old SOL bundle is rejected. The new receipt
  pins premerged weights; applying Turbo again is rejected. Preparation processes
  tensors individually, avoiding a second whole BF16 checkpoint. Temporary mapped
  tensors need uncached lifetimes so replaced base buffers do not remain resident.
- **RoPE precision:** compute angles in FP32 and BF16-round cosine/sine as upstream
  specifies. Table agreement alone did not resolve the duplicate-person case.
- **X2 artifacts:** a large-array temporal copy required bounded chunks; RGB channel
  packing and sampling/delivery geometry needed explicit contracts. Alignment padding
  must be cropped correctly on the ordinary 768p path. Larger decoded frames alone do
  not establish better detail, and low-resolution generated geometry can already be
  wrong before X2. The same-latent ordinary/Lanczos controls retain those failures.
- **Performance discipline:** packed-QKV activation reuse is adopted; a later fused
  QKV projection candidate was not, because complete-block timing regressed despite
  numerical agreement. Fine-attention-only estimates are not whole-video speedups.
  Further VSA micro-optimization stopped when profiling did not support a worthwhile
  simple gain. No unqualified diagnostic attention switches were added to the API.

The release preserves both modes because scene-level tradeoffs survive the fixes.
New public releases still need versioned artifacts and their publication validation;
these source-checkout results do not certify untested hardware, longer durations or
unseen tasks.
