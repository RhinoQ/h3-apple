# 0.7.0 — Faster X2 generation and corrected SOL models

**VSA remains the default; SOL remains an explicit alternative.**
Both use original LightX2V Ref2VA Turbo four-step v0.1. SOL now merges Turbo into the
BF16 base before W8G64 preparation, fixing the observed duplicate-person regression
in the qualified cases. Optional X2 supports landscape and portrait at 544p/576p.
Ordinary 768p remains available; **768p + X2 has been removed** from the public API.

The release includes the wheel, source archive, matching native engine, Ref2VA
skill and SHA256 checksums. SOL downloads its pinned engine automatically.
See [installation and model migration](../install.md). Existing VSA models can
be reused; old quantized SOL bundles must be prepared again from original sources.

## Speed versus 0.6.0

The new speed option is **544p sampling + X2 decoding**, compared with ordinary
768p generation available in 0.6.0. It keeps four denoising forwards and outputs
1920×1088 landscape or 1088×1920 portrait. The gain comes from sampling fewer
spatial tokens; it is not a faster implementation of the same 768p computation.

The [installed-wheel release check](../evidence/v0.7.0-release-check.json) used the
same cloud-palace prompt, reference and seed: VSA 0.6.0 native 768p took
**573.37 s**, versus **211.43 s** for VSA 0.7.0 at 544p + X2
(**2.71×**). This is one sequential pair, 0.6.0 first, with OS caches
not flushed; it is not a repeated or equal-quality performance estimate.

The wider [twelve-case benchmark](https://rhinoq.github.io/h3-apple/) measures the
same options within a frozen 0.7.0 build on a 40-core M5 Max, 128 GiB:

| Mode | Native 768p median | 544p + X2 median | Median paired speedup |
| --- | ---: | ---: | ---: |
| VSA | 529.28 s | 259.14 s | **2.07×** |
| SOL | 363.58 s | 193.87 s | **1.91×** |

These are full API calls with prepared models, twelve five-second scenes and one
run per route/case. Paired ratios are not ratios of the displayed medians. Quality
is scene-dependent: motion, small faces, framing and text can change. No lossless
quality or universal speed guarantee is implied. SOL premerge is a correctness
change, not an acceleration claim; its controlled integration pair was 7.15% slower.

VSA's W8A8, shared QKV activation packing and INT8 QK already shipped in 0.6.0.
They remain in 0.7.0; this release does not claim them as new optimizations.

Maintenance removes private experiment overrides and unused Wan/training code.
The public generation contract and retained numerical helpers are unchanged.
Frozen benchmark videos remain bound to their recorded build.
Cancellation no longer fails on macOS after the worker group has already exited;
permission errors against live processes are still reported.

## Choose a mode

| Mode | Useful observed behavior | Observed limitations |
| --- | --- | --- |
| VSA, default | Lower physical memory; better action-count or graphic-trajectory control in some comparisons | Reframing, partial face cropping and architectural geometry drift in other cases |
| SOL, optional | Faster complete calls in the frozen comparison; stronger composition in several portrait/architecture cases | More physical memory; repeated actions and overshoot/return in some tasks; not uniformly better quality |
| 544p + X2, either mode | Lower sampling cost and larger decoded frames; landscape and portrait supported | Reconstructs detail rather than recovering a high-resolution ground truth; cannot repair failed motion, identity or composition |

Use explicit `--mode VSA` / `--mode SOL`, and `--resolution 544p --x2` for the fast
profile. This profile name describes the benchmark request, not a new CLI flag.
Five-second tests are useful for iteration. Same seed across modes does not imply the
same random tensors, implementation or output. Neither mode silently falls back to the
other. See [X2 examples](../x2.md), [SOL migration](../install.md#upgrading-sol-models)
and [the public API](../api.md).

## Descriptive benchmark

[Benchmark 0.3.0](https://rhinoq.github.io/h3-apple/) contains twelve challenging
five-second scenes at four routes: VSA/SOL, standard 768p/fast 544p + X2.
Every output is regenerated on the same frozen 0.7.0 build. Historical prompts
and references may be reused; historical videos and grades are excluded.
All 48 outputs are reviewed and scored. The page includes prompts, unmodified
references, requests, source/model identities, criterion judgments, frame evidence
and replay.

The main score is confirmed complete visual-task passes divided by all registered
slots. Borderline results are not confirmed passes. Quality severity, complete API
time and sampled peak memory are separate. One seed per case and two profiles per
mode do not make twenty-four independent scenes. Reviews cover all sequential
frames and selected originals, not subjective audio or continuous playback.
This exposed regression suite does not establish a universal quality ranking.

The earlier five-case comparison remains [historical evidence](../evidence/v0.7.0-benchmark.json).
Its results belong to that recorded build and are not pooled into the new edition.

## Fixes and lessons that affected adoption

- **SOL duplicate-person regression:** applying Turbo at runtime to a quantized base
  and merging it into BF16 before quantization are different numerical recipes.
  FP32 merge → BF16 rounding → W8G64 preparation removed the observed duplication in
  the regression and two fresh portrait/landscape gates. It did not make every motion
  correct. The [controlled evidence](../evidence/sol-premerge-source.json) does not
  prove a universal vpipe bug, an incorrect SOL attention operator or bad adapter binding.
- **Prepared-model compatibility:** the old SOL bundle is rejected. The new receipt
  pins premerged weights; applying Turbo again is rejected. Preparation processes
  tensors individually, avoiding a second whole BF16 checkpoint. Temporary mapped
  tensors need uncached lifetimes so replaced base buffers do not remain resident.
- **RoPE precision:** compute angles in FP32 and BF16-round cosine/sine as upstream
  specifies. Table agreement alone did not resolve the duplicate-person case.
- **Colored grids in long X2 videos:** MLX 0.32.0 selected a 32-bit copy kernel for
  small temporal views despite their large channel strides. In the reproduced
  2,562,195,456-element packed array, reachable offsets overflowed and color data
  was lost, producing a repeating blue/orange grid. The released implementation
  sends the final concatenation to the CPU stream above the signed-32-bit element
  limit; model decoding stays on the GPU. [Independent tile and long-clip checks](../evidence/v0.7.0-x2-grid-fix.json)
  and a large-array regression distinguish this implementation defect from X2 model quality. RGB
  PixelShuffle ordering was checked and was not the root cause.
- **Geometry contracts:** retain 0.6.0's ordinary-768p alignment crop while keeping
  X2 sampling and delivery sizes separate, in both orientations. X2 pixels are not
  resized. Earlier green borders in the review page were CSS background exposed
  by video sizing, not pixels encoded in the video. A wrong sampled scene or
  softened detail remains a quality limitation.
- **Performance discipline:** packed-QKV activation reuse is adopted; a later fused
  QKV projection candidate was not, because complete-block timing regressed despite
  numerical agreement. Fine-attention-only estimates are not whole-video speedups.
  Further VSA micro-optimization stopped when profiling did not support a worthwhile
  simple gain. No unqualified diagnostic attention switches were added to the API.

The release preserves both modes because scene-level tradeoffs survive the fixes.
The benchmark's original build stays immutable. Release packaging changes its
engine download location, not inference code or engine bytes. These results do
not certify untested hardware, longer durations or unseen tasks.
