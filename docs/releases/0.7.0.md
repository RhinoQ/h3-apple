# 0.7.0 — SOL + X2 by default

- **Default output:** SOL + 544p/X2 in landscape and portrait.
- **Simpler install:** both modes and X2 included; face enhancement removed.
- **SOL fix:** Turbo premerge resolves the tested duplicate-person regression.
- **X2 fix:** bounded copying prevents the reproduced colored-grid artifact.

VSA remains available with `--mode VSA`. Both modes use original LightX2V Ref2VA
Turbo four-step v0.1. Native 768p remains; **768p + X2 is removed**.

[Install or upgrade](../install.md). Compatible VSA models are reusable;
older quantized SOL weights need preparation from original sources.
The release includes the wheel, sdist, engine, skill, manifest and checksums.

## Speed versus 0.6.0

**544p + X2 reduces sampling work**, then decodes to 1920×1088 landscape or
1088×1920 portrait. This changes resolution and quality, not just execution speed.

The [direct release check](../evidence/v0.7.0-release-check.json), using the same
cloud-palace prompt, reference and seed, measured **573.37 s → 211.43 s (2.71×)**
from VSA 0.6.0 native 768p to VSA 0.7.0 544p + X2. One sequential pair, 0.6.0
first, caches not flushed; neither repeated timing nor equal quality was established.

The [12-scene benchmark](https://rhinoq.github.io/h3-apple/) compares configurations
within one frozen 0.7.0 build on a **40-core M5 Max / 128 GiB**:

| Mode | Native 768p median | 544p + X2 median | Paired median speedup |
| --- | ---: | ---: | ---: |
| VSA | 529.28 s | 259.14 s | **2.07×** |
| SOL | 363.58 s | 193.87 s | **1.91×** |

Full API calls, prepared models, five-second videos, one run per configuration.
Speedups use within-scene ratios, not ratios of the displayed medians.
Motion, faces, framing and text can change. SOL premerge fixes correctness;
its controlled integration pair was **7.15% slower**.

VSA W8A8, QKV activation reuse and INT8 QK already shipped in 0.6.0.

## Choose a mode

| Mode | Strengths in these tests | Limits |
| --- | --- | --- |
| VSA | Lower memory; better action-count/graphics control in some cases | Reframing, face crops, architectural drift |
| SOL | Faster; stronger composition in several cases | Higher memory, repeated actions, overshoot/return |
| X2, either mode | Faster sampling and larger frames | Reconstructed detail; cannot fix failed motion or composition |

SOL + 544p/X2 is the default. Use `--mode VSA` for VSA; select native output
with `--resolution 768p --no-x2` (Python: `resolution="768p", x2=False`).
Neither mode silently falls back. Equal seeds do not imply equal noise or pixels.
[X2 examples](../x2.md) · [SOL migration](../install.md#upgrading-sol-models) · [API](../api.md)

## Descriptive benchmark

[Edition 0.3.0](https://rhinoq.github.io/h3-apple/) includes **12 scenes × 4 configurations**,
all freshly generated and reviewed. Prompts, references, settings, source/model
identities, frame evidence and replay are public.

Task success requires every visual criterion to pass; borderline results do not
count. Quality, time and memory are separate. Agent review covers all sequential
frames and selected originals, with methods disclosed; audio and normal-speed
playback are unscored. Two profiles of 12 scenes are not 24 independent tasks.
This exposed, single-seed suite does not establish a universal ranking.

[Earlier five-case results](../evidence/v0.7.0-benchmark.json) remain separate.

## Fixes and lessons that affected adoption

- **Duplicate subjects:** FP32 Turbo merge → BF16 rounding → W8G64 preparation
  removed the observed duplication in the regression and two fresh cases.
  [Evidence](../evidence/sol-premerge-source.json) supports this recipe change,
  not a universal vpipe/SOL defect or a guarantee of correct motion.
- **Model compatibility:** receipts require premerged weights and reject double
  Turbo application. Per-tensor conversion and uncached base buffers avoid
  retaining a second whole BF16 model.
- **RoPE:** FP32 angles and BF16-rounded cosine/sine follow upstream. Table
  agreement alone did not fix the duplicate-person case.
- **Colored X2 grids:** MLX 0.32.0 used 32-bit offsets for temporal views of a
  2,562,195,456-element array. Overflow lost color data. Final concatenation now
  uses the CPU above the signed-32-bit limit; decoding stays on GPU.
  [Tile, long-clip and regression checks](../evidence/v0.7.0-x2-grid-fix.json)
  distinguish this copy bug from model quality. PixelShuffle was not the cause.
- **Geometry:** retain native-768p cropping and separate X2 sampling/output sizes.
  X2 output is not resized. Green preview borders came from CSS, not encoded pixels.
- **Cancellation:** exited macOS worker groups no longer cause cancellation errors;
  permission errors involving live processes still surface.
- **Cleanup:** removed private experiment overrides and unused Wan/training code.
  Fused QKV projection was rejected because full-block timing regressed;
  activation-pack reuse remains.

This refreshed 0.7.0 changes defaults and removes the face-enhancement runtime,
commands, models manifest and dependencies. Existing 0.7.0 users must reinstall
with `--force-reinstall --no-cache-dir`. Generation kernels and engine bytes are
unchanged; the benchmark retains its original frozen wheel and results.
[Refresh validation](../evidence/v0.7.0-refresh.json): 219 tests and three installed
five-second replays with identical decoded RGB and PCM.
The evidence does not qualify other hardware, durations or unseen tasks.
