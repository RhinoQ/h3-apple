# 0.7.0 — Faster video generation on Mac

**A five-second video with sound in about three minutes.** The default SOL + X2
mode took **3m 14s median** across 12 scenes on a 40-core M5 Max with 128 GiB.

[Install](../install.md) · [Watch the benchmark](https://rhinoq.github.io/h3-apple/)

## What's new

- **Faster by default.** SOL generates at 544p, then X2 reconstructs larger frames.
  Landscape output is 1920×1088; portrait is 1088×1920.
- **Two modes, one workflow.** SOL and VSA both support X2 through the same CLI
  and Python API. Choose SOL for speed or try VSA for lower memory use.
- **Simpler setup.** One package includes both modes and X2, with automatic model
  preparation.

## How much faster?

In one comparison with 0.6.0, the same cloud-palace prompt, image and seed
took **9m 33s → 3m 31s (2.71× faster)**: VSA native 768p versus VSA 544p + X2.
[Exact timings and setup](../evidence/v0.7.0-release-check.json).

Across the 12-scene benchmark, both modes benefit from X2:

| Mode | Native 768p | 544p + X2 | Median speedup |
| --- | ---: | ---: | ---: |
| **SOL**, default | 6m 04s | **3m 14s** | **1.91×** |
| **VSA** | 8m 49s | **4m 19s** | **2.07×** |

Median full-call times for five-second videos with prepared models on the Mac
above, rounded to seconds. One run per scene/configuration. Speedups are medians
of paired scene ratios. X2 trades some original detail for speed; faces, text,
motion and framing can differ from native 768p. [Compare the videos](https://rhinoq.github.io/h3-apple/).

## Fixes you can see

- **Duplicate people in SOL:** corrected model preparation removed the duplication
  in our regression and two additional cases. Compatibility checks also catch old
  SOL weights and accidental double application of Turbo. [Evidence](../evidence/sol-premerge-source.json).
- **Colored grids in X2:** fixed a memory-copy overflow that corrupted frame colors.
  [Regression and long-clip checks](../evidence/v0.7.0-x2-grid-fix.json).
- **Cleaner cancellation:** stopping a run handles workers that have already exited.

## Choose your output

SOL + X2 is the default. Use `--mode VSA` to try VSA or
`--resolution 768p --no-x2` for native 768p.

In these tests, SOL was faster and often preserved framing better. VSA used less
memory and handled action counts or graphics better in some scenes. Both can
miss motion instructions or distort faces and architecture; results vary by scene.

Compatible VSA models can be reused. Older SOL models need
[fresh preparation](../install.md#upgrading-sol-models). Native 768p remains
available; 768p + X2 has been removed. [Settings and examples](../x2.md).

## Tested and reproducible

[Release checks](../evidence/v0.7.0-refresh.json): **219 tests passed** and three
five-second CLI/Python videos matched their reference outputs in every decoded
frame and audio sample.

The [benchmark](https://rhinoq.github.io/h3-apple/) contains **12 scenes × 4 configurations**,
including failures, with prompts, reference images, settings and replay instructions.
Task success, visual quality, speed and memory are reported separately. Agent
review covers all frames with methods disclosed; audio and normal-speed playback
are unscored. Each scene uses one seed, so results describe this test set.
