# Optional X2 decoding

Version 0.7.0 adds `--x2` / `x2=True` to VSA generation. This source version also
accepts `--mode SOL --x2`. It uses the
[MiniMax H3 X2 Detail VAE](https://huggingface.co/speach1sdef178/MiniMax-H3-X2-Detail-VAE)
to decode the generated latent at twice the ordinary output width and height.
It keeps the original LightX2V four-step sampling and generated audio. X2 is off
by default and requires the existing `[VSA]` Python dependencies, including when
sampling with SOL. SOL + X2 requires Python 3.11 and uses SOL generation models,
followed by the same MLX X2 decoder; it does not require the VSA model bundle.

## Choose the sampling resolution

`--resolution` controls sampling, before X2. Choose 544p to reduce denoising work,
or 768p to keep native 768p sampling and produce larger output. Native 768p plus
X2 adds decode work; it is not a speed optimization.

| Sampling setting | Landscape sampling canvas | X2 landscape output | X2 portrait output |
| --- | --- | --- | --- |
| `544p` | 960 × 544 | 1920 × 1088 | 1088 × 1920 |
| `576p` | 1024 × 576 | 2048 × 1152 | 1152 × 2048 |
| `768p` | 1376 × 768 | 2732 × 1536 | 1536 × 2732 |

544p is available only with X2. The portrait sampling canvas swaps the width
and height. Reference-image preprocessing follows the sampling canvas area.
All X2 pixels are retained apart from the existing 768p alignment padding:
10 pixels are cropped from each horizontal edge in landscape (vertical edge
in portrait) after decoding. There is no output downscaling. The aligned 544p
canvas has an approximate 16:9 ratio, so its output is 1920 × 1088, not 1080p.

```bash
# Lower sampling cost, landscape
h3 generate --image landscape.jpg --prompt-file scene.txt --duration 5 \
  --resolution 544p --x2 --aspect-ratio 16:9 --output landscape-x2.mp4

# SOL sampling followed by X2, portrait
h3 generate --mode SOL --image portrait.jpg --prompt-file scene.txt --duration 5 \
  --resolution 544p --x2 --aspect-ratio 9:16 --output portrait-sol-x2.mp4

# Higher sampling resolution, portrait
h3 generate --image portrait.jpg --prompt-file scene.txt --duration 5 \
  --resolution 768p --x2 --aspect-ratio 9:16 --output portrait-x2.mp4
```

```python
from h3_apple import generate, resolve

settings = dict(prompt_file="scene.txt", reference_images=["portrait.jpg"],
                duration=5, resolution="544p", aspect_ratio="9:16", x2=True)
print(resolve(**settings).to_dict())  # no downloads or model loading
result = generate(**settings, output="portrait-x2.mp4")
```

## Model preparation

The first X2 generation prepares the additional **5.25 GB** decoder and its
LICENSE/NOTICE under `~/Models/h3-apple/x2`. Existing models for the selected
generation mode are reused.
Weights are pinned by revision, size and SHA256; an invalid existing file is
reported and preserved. Partial downloads resume. To prepare separately or
reuse files already downloaded from the author:

```bash
h3 prepare-x2 --plan
h3 prepare-x2 --reuse-dir /path/to/downloaded-x2
```

For another directory, use `h3 prepare-x2 --model-dir /Volumes/Models/x2`,
then `h3 generate --x2 --x2-model-dir /Volumes/Models/x2 ...`.
The Python equivalent is `generate(..., x2=True, x2_model_dir="/Volumes/Models/x2")`.
Generation checks the combined pending generation-model and X2 download against the 20 GB
consent threshold before either preparation starts. Ordinary generation does
not download X2. Setup and verification time are excluded from generation's
`elapsed_seconds`.

Run records distinguish sampling geometry (`model_width`, `model_height`)
from delivered geometry (`width`, `height`), and record `x2` plus the additional
checkpoint identity and decoder recipe in `x2_model`.
SOL + X2 additionally records the normalized latent layout and checksum, lossless
float32 audio handoff, and MLX decoder backend. It skips the ordinary native video
decoder. Selecting SOL changes the complete sampling backend and its random
stream; an equal seed does not imply the same latent or output as VSA. Speed and
quality measurements below apply to VSA + X2, not SOL + X2.

## Local integration measurements

Six five-second clips completed on a 40-core M5 Max with 128 GiB and macOS
26.6.1. Four X2 clips cover both orientations and 544p/768p sampling. The ordinary
768p path reproduced the full decoded RGB and PCM of 0.6.0 exactly for the tested
landscape input. Source, weights, complete prompts, input hashes, environment,
measurements, the preflight failure and review scope are retained in the
[integration record](evidence/v0.7.0-x2-integration.json).

| Method | Landscape generation | Portrait generation |
| --- | ---: | ---: |
| 544p + X2 | 213.85 s | 232.05 s |
| 768p + X2 | 506.02 s | 508.09 s |
| Ordinary 768p, 0.7.0 | 468.97 s | Not measured |

These are individual complete-generation calls, excluding model preparation.
For the landscape input, 544p + X2 took 2.19× less time than ordinary 768p;
768p + X2 took 1.079× as long. Low-resolution sampling changes the latent and
reference budget, so this is a route comparison, not isolated decoder quality.
No repeated-performance or imperceptible-quality claim is made. The four X2
frame sequences showed no severe pipeline color corruption; detail softness and
foreground cropping remain visible. Original audio is retained but was not judged.

## Quality and execution boundaries

X2 reconstructs detail from the sampled latent. It cannot repair incorrect
motion, cropped faces, story continuity or geometry already present in that
latent. Lower-resolution sampling can change those features even at the same
seed. Small faces, moving graphics, text and action need close inspection;
sharpened contours, halos or unstable textures can appear. Larger pixel
counts do not guarantee better perceived quality. The author's separate B32
reference-image enhancer is not enabled by `--x2`.

Start with five-second clips. Generation has the same device lock, cancellation,
resource monitoring and media validation as ordinary VSA. Large packed videos
use a CPU final temporal copy to avoid the MLX 0.32.0 integer-offset bug;
decoder tiles still run on the GPU. This fixes that implementation defect,
not every possible color artifact or model failure.
